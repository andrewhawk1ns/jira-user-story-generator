# Jira Field Mapping Contract

**Branch**: `001-ai-user-story-generator` | **Date**: 2026-05-03

This is the single authoritative mapping between the internal `generated_stories` shape and Jira issue fields. The implementation lives in `lib/jira/field-mapping.ts`. All Jira push operations MUST use this mapping — no ad-hoc field construction elsewhere.

---

## Story → Jira Issue Field Mapping

| Internal Field | Jira Field | Notes |
|---|---|---|
| `title` | `summary` | Direct string mapping |
| `userStoryStatement` | `description` (ADF heading) | Rendered as an Atlassian Document Format (ADF) document — see below |
| `acceptanceCriteria` | `description` (ADF section) | Given/When/Then items rendered as a bulleted list under "Acceptance Criteria" heading |
| `priority` | `priority.name` | Mapped via priority table below |
| `labels` | `labels` | Array of strings; Jira labels must be single words (spaces replaced with `_`) |
| `storyPoints` | `story_points` field (custom) | Written to the configured story points custom field ID (`JIRA_STORY_POINTS_FIELD_ID` env var); omitted if null |
| `session.jiraProjectKey` | `project.key` | From the active session's project |
| `session.jiraEpicId` | `parent` (epic link) | Set when session has an `epicId`; uses `parent` field for next-gen projects |
| `session.jiraSprintId` | `sprint` (custom field) | Set when session has a `sprintId`; uses `JIRA_SPRINT_FIELD_ID` env var |
| `blockedBy` | Issue link (`is blocked by`) | Created via a **separate** `POST /rest/api/3/issueLink` call after issue creation — see below |
| `blocks` | Issue link (`blocks`) | Created via a **separate** `POST /rest/api/3/issueLink` call after issue creation — see below |

## Issue Link Dependencies

Jira issue links cannot be set in the initial issue creation payload. They must be created separately using the [Issue Link API](https://developer.atlassian.com/cloud/jira/platform/rest/v3/api-group-issue-links/#api-rest-api-3-issuelink-post) **after** the issue is created.

### Data model fields

The `generated_stories` table includes:

```ts
blockedByIssueKeys: string[]  // Jira issue keys this story is blocked by (e.g. ["PROJ-12"])
blocksIssueKeys: string[]     // Jira issue keys this story blocks
```

Both fields are editable during the review step and default to `[]`.

### Push sequence

1. `POST /rest/api/3/issue` — create the Jira issue, receive the new issue key.
2. For each entry in `blockedByIssueKeys`:
   ```json
   POST /rest/api/3/issueLink
   {
     "type": { "name": "Blocks" },
     "inwardIssue":  { "key": "<blockedByKey>" },
     "outwardIssue": { "key": "<newIssueKey>" }
   }
   ```
3. For each entry in `blocksIssueKeys`:
   ```json
   POST /rest/api/3/issueLink
   {
     "type": { "name": "Blocks" },
     "inwardIssue":  { "key": "<newIssueKey>" },
     "outwardIssue": { "key": "<blocksKey>" }
   }
   ```

### Link type name

The `"Blocks"` link type name is the Jira default. If a Jira instance uses a custom name, the env var `JIRA_BLOCKS_LINK_TYPE` overrides it (default: `"Blocks"`).

### OAuth scope required

Creating issue links requires the `write:jira-work` scope, which is already in the declared scope list.

### Error handling

If an issue link call fails (e.g. the referenced key does not exist), the push operation logs the failure per-link but does **not** roll back the created issue. Partial failures are surfaced in the `/api/jira/push` response under a `linkErrors` array.

## Priority Mapping

| Internal | Jira |
|---|---|
| `highest` | `Highest` |
| `high` | `High` |
| `medium` | `Medium` |
| `low` | `Low` |
| `lowest` | `Lowest` |
| `null` / undefined | _(omitted — Jira uses project default)_ |

## Jira Description ADF Structure

The `description` field is constructed as an ADF document with this structure:

```
[Heading 3] User Story
  [Paragraph] {userStoryStatement}

[Heading 3] Acceptance Criteria
  [BulletList]
    [ListItem] Given {given} / When {when} / Then {then}
    ...

[Heading 3] Source
  [Paragraph] Generated by AI User Story Generator — Session {sessionId}
```

## Environment Variables Required

| Variable | Description |
|---|---|
| `JIRA_STORY_POINTS_FIELD_ID` | Custom field ID for story points (e.g. `customfield_10016`) |
| `JIRA_SPRINT_FIELD_ID` | Custom field ID for sprint (e.g. `customfield_10020`) |
| `JIRA_BLOCKS_LINK_TYPE` | Issue link type name for blocking relationships (default: `"Blocks"`) |

These are project-specific and must be configured per Jira instance. They are documented in `.env.example`.
